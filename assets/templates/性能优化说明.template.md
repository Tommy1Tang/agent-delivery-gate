## 3. 性能瓶颈分析

### 3.1 瓶颈清单

| 瓶颈编号 | 瓶颈描述 | 层级 | 现象 | 根因 | 严重级别 | 影响范围 |
|----------|----------|------|------|------|----------|----------|
| BOT-001 | 订单列表查询慢 | 数据库 | P99 500ms，全表扫描 | 缺少 `idx_user_created` 索引 | 🔴 高 | 所有用户 |
| BOT-002 | Session 每次查 DB | 应用层 | 每次请求 +30ms | 未引入分布式 Session 缓存 | 🟡 中 | 所有需认证请求 |
| BOT-003 | 商品图片加载慢 | 前端/网络 | FCP 3s | 未使用 CDN + 图片未压缩 | 🟡 中 | 所有用户首屏 |

### 3.2 瓶颈详情

#### BOT-001：订单列表查询慢

- **SQL 语句**：`SELECT * FROM orders WHERE user_id = ? ORDER BY created_at DESC`
- **EXPLAIN 结果**：`type: ALL, rows: 5000000`（全表扫描）
- **CPU 使用率**：数据库 CPU 85%（该查询占 60%）
- **建议索引**：`CREATE INDEX idx_user_created ON orders(user_id, created_at DESC)`

## 4. 缓存策略设计

### 4.1 缓存层级架构

```text
┌─────────────────┐
│  浏览器缓存      │ ← Cache-Control / ETag / Service Worker
├─────────────────┤
│  CDN 缓存       │ ← 静态资源 (图片/CSS/JS)，TTL 7d
├─────────────────┤
│  本地缓存        │ ← Caffeine / LRU Map，热点配置数据
├─────────────────┤
│  分布式缓存      │ ← Redis，Session / 热点业务数据
├─────────────────┤
│  数据库          │ ← PostgreSQL，持久化存储
└─────────────────┘
```

### 4.2 各层缓存配置

| 缓存层 | 数据类型 | TTL | 最大容量 | 淘汰策略 |
|--------|----------|-----|----------|----------|
| 浏览器 | 静态资源 | 7d | - | - |
| CDN | 图片/CSS/JS | 7d | - | LRU |
| 本地缓存 | 配置/字典 | 5min | 1000 条 | LRU |
| Redis | Session | 30min | 2GB | allkeys-lru |
| Redis | 商品详情 | 10min | 1GB | allkeys-lru |

### 4.3 缓存风险防护

| 风险类型 | 场景 | 防护策略 |
|----------|------|----------|
| 缓存雪崩 | 大量缓存同时过期 | TTL 加随机偏移 ±20% |
| 缓存击穿 | 热点 Key 过期瞬间高并发查 DB | 互斥锁 + 异步刷新 |
| 缓存穿透 | 查询不存在的数据穿透缓存 | 布隆过滤器 + 空值缓存 1min |

## 5. 优化方案

### 5.1 优化项清单

| 优化编号 | 优化项 | 层级 | 方案 | 预期收益 | 风险 | 优先级 |
|----------|--------|------|------|----------|------|--------|
| OPT-001 | 添加订单查询索引 | 数据库 | `CREATE INDEX idx_user_created ON orders(user_id, created_at DESC)` | P99 500ms→50ms | 写入性能 -5% | P0 |
| OPT-002 | 商品详情加 Redis 缓存 | 缓存 | Cache-Aside，TTL 10min | QPS 500→2000 | 缓存一致性 | P1 |
| OPT-003 | 静态资源上 CDN | 网络 | 图片/CSS/JS 推送 CDN | FCP 3s→0.8s | 缓存失效策略 | P1 |
| OPT-004 | 接口批量合并 | 应用层 | 合并 5 次独立请求为 1 次批量请求 | 网络往返 -4 次 | 单点故障 | P2 |

### 5.2 OPT-001 详细方案

- **修改文件**：`migrations/V2__add_order_index.sql`
- **SQL**：`CREATE INDEX idx_user_created ON orders(user_id, created_at DESC);`
- **上线方式**：在线 DDL（PostgreSQL 支持 `CREATE INDEX CONCURRENTLY`），避免锁表
- **回滚方案**：`DROP INDEX idx_user_created ON orders;`
