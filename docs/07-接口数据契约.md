# 接口数据契约

> **所属项目**：MES Lite — 轻量级离散制造执行系统
> **文档版本**：v1.0
> **创建时间**：2026-03-18
> **设计角色**：Data Contract Designer
> **上游依赖**：`docs/01-需求规格书.md`（已冻结，FR/AC/BR/NFR/枚举的唯一来源）、`docs/04-详细设计说明书.md`
> **演示说明**：本文档是 MES Lite 通用离散制造演示交付的一部分；所有编号、示例数据与地址均为虚构，不对应任何真实企业或生产环境。

## 1. 契约范围

### 1.1 覆盖范围

| 项 | 内容 |
| --- | --- |
| 覆盖能力 | CAP-001 工单管理、CAP-002 生产排程、CAP-003 设备状态监控、CAP-004 物料批次追溯、CAP-005 质量检验记录，以及 FR-015 角色权限与操作审计 |
| 覆盖需求 | FR-001 ~ FR-015；验收对齐 AC-001 ~ AC-030；规则对齐 BR-001 ~ BR-015；性能口径对齐 NFR-001 ~ NFR-003 |
| 端点总数 | 31 个（工单族 7、排程族 4、设备族 6、追溯族 4、检验族 6、权限与审计族 4） |
| 协议与风格 | HTTP/1.1 + REST/JSON；UTF-8；状态变更使用动作子资源；路径前缀 `/api` |
| 调用方 | Vue 3 + Element Plus 单页应用、设备网关（仅状态上报端点） |
| 不在本契约内 | ERP / 财务 / 采购对接（需求范围外）；PLC 直连协议；标签打印指令；移动端 App |

### 1.2 契约效力

- 本契约是前端、后端、QA 与设备网关集成方的字段口径唯一来源；出现分歧时以本文件为准，改动需同步更新本文件与 `docs/04-详细设计说明书.md`。
- 枚举取值与错误码符号不得由实现侧自行新增近义值；新增需走变更流程并回归 `docs/01-需求规格书.md`。
- 本文档为**首版基线**，破坏性变更检测结果见第 11 节。

### 1.3 不在本契约内但受其约束的内容

| 项 | 说明 |
| --- | --- |
| 分页 `total` 精度 | 超过 10 万行时返回估算值并置 `totalIsEstimate = true` |
| 审计写入时机 | 异步写入，但契约上保证「接口成功返回即已受理审计」（NFR-006） |
| 部分成功语义 | Excel 导入与 OEE 缺数场景返回 200 + `partial = true` 与明细清单 |
| 幂等 | 状态变更以 `version` 乐观锁实现；设备上报以 `reportKey` 归一化窗口实现 |

## 2. 术语与对象定义

| 术语 | 英文 / 标识 | 定义 | 来源 |
| --- | --- | --- | --- |
| 工单 | Work Order (`workOrderId`, `woNo`) | 一次生产任务，含产品、计划数量、计划起止时间与状态 | FR-001 |
| 工序 | Operation (`operationCode`, `seqNo`) | 工单对应的工艺路线工序，携带标准工时与是否需检验 | FR-004、FR-012 |
| 报工 | Report (`goodQty`, `scrapQty`) | 操作工或班组长提交的合格与报废数量 | FR-002 |
| 排程任务 | Schedule Task (`scheduleTaskId`) | 工单某道工序在某设备上的时间占用 | FR-004 |
| 设备 | Equipment (`equipmentCode`) | 产线设备台账与当前状态 | FR-007 |
| 停机 | Downtime (`downtimeReasonCode`) | 设备处于 DOWN / MAINTENANCE 的时段 | FR-008、BR-006 |
| 告警 | Alarm (`alarmId`, `level`) | 设备异常生成的待处理事件，P0 / P1 / P2 | FR-008 |
| 物料批次 | Material Batch (`materialBatchNo`) | 一次收货形成的可投料单元，含供应商批次与数量 | FR-009 |
| 投料记录 | Feeding (`feedQuantity`, `feedTime`) | 工单消耗某批次的数量、时间与操作人，同时作为追溯边 | FR-010、FR-011 |
| 追溯 | Trace (`direction`, `partial`) | 按锚点在投料记录上正向或反向遍历 | FR-011 |
| 检验单 | Inspection Order (`inspectionNo`) | 一次检验活动，含检验项集合与判定结果 | FR-012 |
| 检验项 | Inspection Item (`itemCode`, `measuredValue`) | 单个检验指标的标准值、上下限与实测值 | FR-012、BR-010 |
| 不合格记录 | Nonconformity (`nonconformityId`) | 判定 FAIL 后生成的不合格事实 | FR-013 |
| 处置单 | Disposal Order (`disposalOrderId`) | 对不合格品的 REWORK / CONCESSION / SCRAP 处置与审批 | FR-014 |
| 审计日志 | Audit Log (`auditLogId`) | 关键写操作的留痕，不可修改与删除 | FR-015、BR-015 |
| 数据范围 | Data Scope (`ALL` / `SELF_TEAM` / `SELF`) | 角色可访问数据的范围过滤口径 | BR-014 |
| 部分成功 | partial | 结果不完整但请求成功（缺数、断链）的显式标记 | AC-016、AC-022 |

## 4. 请求参数契约

### 4.1 公共请求头

| 字段 | 类型 | 必填 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `Authorization` | string | 是 | — | `Bearer <accessToken>` | 设备网关使用独立主体令牌，仅可访问状态上报端点 |
| `Content-Type` | string | 条件必填 | `application/json` | 写接口必填 | 导入与导出使用 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| `X-Trace-Id` | string | 否 | 服务端生成 | 8-32 位 `[A-Za-z0-9-]` | 调用方传入时全链路沿用，便于对账审计与日志 |
| `Accept-Language` | string | 否 | `zh-CN` | `zh-CN` / `en-US` | 仅影响 `message` 文案语言，`code` 不变 |

### 4.2 公共分页与排序参数

| 字段 | 类型 | 必填 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `page` | integer | 否 | 1 | ≥ 1 | 页码从 1 开始 |
| `size` | integer | 否 | 20 | 1 ~ 100 | 超过 100 返回 400 + `PARAM_INVALID` |
| `sort` | string | 否 | 各端点见 9.2 | `field,asc` 或 `field,desc` | 字段必须在端点白名单内，非法字段返回 400 + `PARAM_INVALID` |

### 6.3 错误码维护约定（S3-2 冲突检测）

1. 错误码符号在 `ErrorCode` 枚举中单一定义，字段为 `code`、`httpStatus`、`module`、`message`；符号全局唯一，重复定义在编译期与启动自检双重失败。
2. 按能力域分段：CAP-001 `PRODUCT_` / `TIME_RANGE_` / `START_` / `DAILY_WO_` / `MATERIAL_NOT_FED` / `QTY_` / `SCRAP_REASON_` / `QC_` / `WORK_ORDER_`；CAP-002 `NO_ELIGIBLE_` / `SCHEDULE_` / `EQUIPMENT_UNAVAILABLE` / `OUTSIDE_SHIFT_` / `REASON_`；CAP-003 `EQUIPMENT_NOT_FOUND` / `ALARM_` / `HANDLE_RESULT_`；CAP-004 `MATERIAL_NOT_FOUND` / `BATCH_` / `QUANTITY_` / `INSUFFICIENT_` / `OVER_ISSUE_` / `TRACE_`；CAP-005 `INSPECTION_` / `MEASURED_` / `LIMIT_` / `JUDGE_` / `DISPOSAL_` / `SCRAP_APPROVAL_` / `APPROVAL_`；FR-015 `DATA_SCOPE_` / `ROLE_` / `AUDIT_`。
3. 通用码 `PARAM_INVALID`、`VERSION_CONFLICT`、`SYSTEM_ERROR` 为跨能力域共享，符号已在需求规格书固定，不得重命名。
4. `message` 仅用于开发与日志检索；用户可见文案由前端 `src/utils/errorCode.ts` 映射，后端不得返回面向现场的完整中文长句。

## 9. 分页、筛选、排序规则

### 9.1 分页规则

1. 所有列表端点统一使用 `page`（1 起）、`size`（默认 20，上限 100）与 `PageResult<T>` 五字段 + `totalIsEstimate`。
2. 无数据时 `list = []`、`total = 0`、`pages = 0`；禁止返回 `null`。
3. `total` 超过 10 万行时返回估算值并置 `totalIsEstimate = true`，前端必须提示「收窄筛选条件以获取精确总数」。
4. 结果集上限：追溯查询 1000 条（超出置 `truncated = true`）；导出端点不受分页限制但受区间与行数上限约束。

### 9.2 各端点默认排序与白名单

| `SELF_TEAM` | 工单、排程、设备、检验 | 仅返回 `teamCode` 与当前用户一致的记录 |

数据范围条件由服务端强制注入，客户端传入的任何范围参数一律忽略；越权访问返回 403 + `DATA_SCOPE_FORBIDDEN`（AC-028）。

## 11. 兼容性与版本策略

### 11.1 破坏性变更检测（S3-1）

本契约为首版基线，`breakingChanges: []`。后续版本按下列规则判定：

| 变更 | 类型 | 处理 |
| --- | --- | --- |
| 删除字段 | 破坏 | 升 `/api/v2` 或保留 `deprecated` 过渡期（≥ 1 个迭代） |
| 重命名字段 | 破坏 | 同上 |
| 修改字段类型（如 `integer` → `string`） | 破坏 | 同上 |
| 字段从可选变为必填 | 破坏 | 同上 |
| 枚举减项 | 破坏 | 同上 |
| 修改 HTTP 状态码或错误码语义 | 破坏 | 同上 |
| 新增可选字段 | 兼容 | 可直接发布 |
| 新增端点 | 兼容 | 可直接发布 |
| 枚举增项（单位、报废原因等字典类） | 兼容 | 前端必须对未知枚举值做兜底展示 |

### 11.2 版本与废弃策略

1. 主版本体现在路径前缀（`/api` → `/api/v2`），不在请求头中隐式切换。
2. 废弃字段在响应中保留并标注 `@Deprecated`，契约文档同步标记 `deprecated: true`，过渡期不少于 1 个迭代。
3. 契约变更必须同时更新本文件、`docs/04-详细设计说明书.md` 与前端 `src/api/` 类型定义，并运行契约漂移检查（`contract_drift_check`）。
4. 每次变更后与本文件上一版本 diff，结果记入 `evidence-ledger.json#/observability/contractDiff`。

### 11.3 其他协议形式适用性

| 形式 | 是否采用 | 说明 |
| --- | --- | --- |
| GraphQL | 否 | 前端无字段裁剪需求，REST 足以覆盖 31 个端点 |
| 消息队列（Kafka / RabbitMQ / Pulsar） | 否 | 部署环境不提供中间件；异步由应用内事务性发件箱（`outbox_event`）承载，无跨系统消息契约 |
| WebSocket / SSE | 否 | 看板以 10s 轮询满足 NFR-002 的刷新要求 |
| gRPC | 否 | 无跨语言内部调用；设备网关使用 REST/JSON 上报 |

## 12. 前端、后端、QA 交接说明

### 12.1 给 Frontend Engineer

- 请求函数集中在 `src/api/`，路径不得硬编码在组件中；统一处理 `Result` 封装与 `PageResult` 分页。
- 错误码文案集中在 `src/utils/errorCode.ts`，与第 6.2 节逐项对应；遇到未知错误码必须展示通用提示并记录 `traceId`，禁止静默失败。
- 需要感知的业务上下文均在 `data` 中：剩余可报数量、冲突任务清单、缺失检验项、断链节点、缺失审批角色。前端应基于这些字段给出可操作提示，而不是仅弹出错误码。
- 分页组件需展示 `totalIsEstimate` 提示；设备看板必须展示 `snapshotAt` 与 `dataDelayed` 标记（ADR-005）。
- 写操作必须回传最新 `version`；收到 `VERSION_CONFLICT` 时自动刷新数据并提示用户重新提交。

### 12.2 给 Backend Engineer

- DTO 校验与第 4 节的必填、默认值与边界一一对应；错误码只允许取自第 6.2 节，禁止新增字符串字面量。
- 状态变更端点必须同时做状态机前置校验与业务规则校验；乐观锁字段由 MyBatis-Plus 维护，冲突统一翻译为 `VERSION_CONFLICT`。
- 响应中的 `data` 必须包含前端可操作上下文；列表端点禁止返回 `null` 集合。
- 时间字段统一使用服务端时间；客户端传入的 `feedTime`、`occurredAt` 需按第 4 节约束校验。
- 审计动作名与 `targetType` 按 8.4 表实现，禁止自定义近义名（AC-029 按动作查询）。

### 12.3 给 Quality Gate Engineer

- 每个端点至少覆盖：1 个成功用例、1 个参数校验失败用例、1 个业务失败用例（错误码与 HTTP 状态须与 6.2 表逐行一致）。
- 重点验证：`version` 并发冲突（AC-006）、排程冲突明细（AC-011）、库存与超领拦截（AC-020）、检验项完整性与上下限容差（AC-023、AC-024）、追溯锚点互斥与断链 `partial`（AC-022）、数据范围越权（AC-028）、审计不可改删（AC-029）。
- 契约测试建议基于 `springdoc-openapi` 导出的 OpenAPI 与前端类型定义做对账，防止文档与实现漂移。
- 性能断言按 NFR-001 ~ NFR-003：查询 P95 ≤ 500ms、写入 P95 ≤ 800ms、单条上报 ≤ 200ms、追溯单层 P95 ≤ 2s。

### 12.4 给设备网关集成方

- 仅需实现 `POST /api/equipments/{equipmentCode}/status-reports`，使用独立主体令牌。
- 上报间隔 5s；同一状态 5s 窗口内重复上报会被幂等忽略并返回 200，网关不得据此判定失败。
- 断网期间本地缓存并在恢复后补传；服务端按 `occurredAt` 与 5s 窗口去重，补传的旧事件不会回退当前状态。

## 13. 风险与待确认项

| 编号 | 类别 | 内容 | 影响 | 处理方式 |
| --- | --- | --- | --- | --- |
| C-R01 | 契约缺口 | 需求规格书未固定 `approvalStatus`、`scheduleStatus`、`alarmStatus` 三个字段的取值集合 | 前后端可能各自定义近义值 | 本契约第 8.1 节冻结取值；如需调整须回写本文件并通知前后端 |
| C-R02 | 精度口径 | 数量字段统一 `NUMERIC(18,3)`，但报工数量为整数、投料数量为小数 | 前端展示与校验不一致 | 报工与计划数量按整数传输；投料、库存按 3 位小数传输（第 7 节已逐字段标注） |
| C-R03 | 分页精度 | `total` 在超过 10 万行时为估算值 | 用户对总数存疑 | 通过 `totalIsEstimate` 显式标记并提示收窄条件 |
| C-R04 | 追溯上限 | `maxDepth` 上限 3、结果集上限 1000 条为推断值 | 深链路调查可能被裁剪 | 响应以 `partial` / `truncated` 标记；压测 PERF-005 后据实调整上限 |
| C-R05 | 时间语义 | 全部时间字段无时区偏移，依赖部署时区固定为 `Asia/Shanghai` | 跨时区部署会歧义 | 部署说明中固定时区；跨时区需求需引入偏移量并升版 |
| C-R06 | 字典枚举 | 单位、报废原因、停机原因为字典驱动，取值可扩展 | 前端可能不识别新增值 | 字典类枚举增项属兼容变更；前端必须对未知值做兜底展示 |
| C-R07 | OEE 口径 | OEE 分母是否含计划保养尚未与设备部门确认（对应设计 Q-03） | 统计口径可能调整 | 契约返回 `availability`、`performance`、`quality` 三项与 `plannedMaintenanceIncluded` 标记，口径变更不改变字段结构 |
| C-R08 | 审计时延 | 审计写入为异步，接口返回时刻可能早于审计落库 | 立即查询审计可能查不到刚刚的操作 | 契约保证「接口成功即已受理审计」；对账以分钟级窗口为准（NFR-006） |
