### Logging（日志）

应用日志为单行 JSON，统一由采集侧解析；自由文本字段在写入前做 CR/LF 中和（对应 `docs/15-安全评审.md` SEC-LOW-06）。

| 字段 | 说明 |
| --- | --- |
| `ts` | ISO 8601 带时区时间戳（`Asia/Shanghai`） |
| `level` | `DEBUG` / `INFO` / `WARN` / `ERROR` |
| `logger` | 日志来源类名 |
| `traceId` / `spanId` | 与追踪联动，可据此刻画单次请求全链路 |
| `userId` / `roleIds` | 操作主体，用于审计对账 |
| `module` | `meslite-workorder` 等模块名，便于按能力域检索 |
| `errorCode` | 业务错误码（如 `QTY_EXCEEDED`），无错误时省略 |
| `msg` | 结构化后的消息正文 |
| `durationMs` | 关键操作的耗时，便于与指标交叉验证 |

日志分级约定：业务校验失败记 `WARN`（可预期，不产生告警）；系统异常与依赖不可用记 `ERROR`（进入告警）；状态迁移、判定、审批等关键写操作记 `INFO` 并同步写入 `audit_log`。安全敏感字段（`password`、`token`、`gatewayToken`）统一脱敏为 `***`。

### Tracing（追踪）

基于 OpenTelemetry，OTLP/HTTP 导出至 `otel-collector.mes-lite.example.com:4318`；采样策略为「10% 概率采样 + 全部错误与全部慢请求（> 1s）强制采样」，避免演示期成本失控同时保留问题现场。

| 跨度 | 关键属性 | 说明 |
| --- | --- | --- |
| `http.server.requests` | `http.route`、`http.status_code`、`userId` | 入口跨度，串联全链路 |
| `workorder.report` | `workOrderNo`、`goodQty`、`scrapQty`、`version` | 报工具业务跨度，含乐观锁版本 |
| `schedule.generate` | `workOrderCount`、`strategy`、`conflictCount` | 排程生成，冲突数用于解释 409 |
| `equipment.status.apply` | `equipmentCode`、`eventSeq`、`stale` | 设备状态落库，`stale=true` 表示被丢弃的过期事件 |
| `feeding.bind` | `materialBatchNo`、`feedQuantity` | 投料与库存扣减 |
| `trace.query` | `direction`、`depth`、`nodeCount` | 追溯查询，`nodeCount` 解释 partial 结果 |
| `audit.persist` | `eventType`、`retryCount` | 审计异步落库 |
| `db.statement` | `db.operation`、`db.sql.table` | 数据库跨度（不含参数值，避免敏感数据入追踪） |

跨模块异步协作经 `outbox_event` 投递，追踪上下文随事件透传，保证「报工 → 工单状态 → 审计」在同一 trace 下可见。
