# 任务清单 — MES Lite 离散制造执行系统

> 下表面向全项目 P0 需求拆分，共 54 条任务（T-001～T-054）。状态枚举：`pending` / `in-progress` / `blocked` / `done`。每任务均给出可复现的验证命令；「输出物」列为计划落盘路径（相对项目根，`backend/` 为 Spring Boot 3 模块、`frontend/` 为 Vue 3 应用、`db/migration/` 为 PostgreSQL 16 迁移脚本）。

### 阶段任务分布

| 阶段 | 任务区间 | 任务数 | 阶段出口判定 |
| --- | --- | --- | --- |
| P0 需求与设计基线 | T-001～T-008 | 8 | 需求与设计文档齐备，工程可编译启动，迁移脚本空库可执行 |
| P1 平台底座与主数据 | T-009～T-016 | 8 | 鉴权、审计、数据范围、主数据与设备台账可用，性能基线建立 |
| P2 核心业务域实现 | T-017～T-045 | 29 | FR-001..FR-014 实现完成，模块单测与集成用例通过 |

### 表头字段说明

| 字段 | 含义 |
| --- | --- |
| 编号 | 任务唯一编号，`T-NNN` 三位顺序编号，在代码注释与提交信息中以 `@trace` 声明引用 |
| 阶段 | 所属交付阶段（P0～P4），与「开发计划」阶段计划一致 |
| 责任角色 | 该任务的唯一负责角色，协作者不在表中体现 |
| 输入依赖 | 开工前必须就绪的任务、需求或外部依赖（DEP-NN）编号 |
| 输出物 | 计划落盘路径；文档类输出物须通过文档结构校验 |
| 优先级 | P0（必须完成）/ P1（重要）/ P2（可选），与需求规格书 AC 优先级一致 |
| 状态 | `pending` / `in-progress` / `blocked` / `done` 四态 |
| 完成标准 | 可机械判定的完成判据，不接受主观描述 |
| 验证方式 | 可直接执行并检查退出码的验证命令 |

### 阻塞升级规则

- 阻塞项连续 3 个工作日无进展时，由责任角色升级至 Architect 协调，并在每周例会披露。
- 需求口径类阻塞（BLK-01、BLK-02）超过最晚解除时间未解决时，按推断值实现并在设计文档标注推断来源，同时登记为变更风险。
- 外部依赖类阻塞（BLK-03、BLK-04）不影响整体排期，但相关任务的验收范围须明确标注为模拟或占位，不得在交付文档中表述为真实对接已完成。
- 阻塞项不改变已冻结的 FR 与 AC 判据，仅影响实现顺序；解除前相关任务不得标记为 `done`，也不得以降低验证标准的方式绕过。
