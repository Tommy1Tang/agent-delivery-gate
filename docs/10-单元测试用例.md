## 测试策略

### 分层策略

| 层次 | 框架 / 工具 | 隔离手段 | 断言重点 |
| --- | --- | --- | --- |
| 领域规则与状态机 | JUnit 5 + AssertJ | 纯对象，无 Mock | 状态迁移矩阵、区间判定、容差规则、错误码 |
| Service | JUnit 5 + Mockito 5 | `@ExtendWith(MockitoExtension.class)`，Mock Mapper、网关客户端、`Clock`、`ApplicationEventPublisher` | 业务规则、调用次数、异常类型与 `ErrorCode`、返回值组装 |

| 架构约束 | ArchUnit | 静态分析 | 分层依赖方向、命名规范 |

### 用例设计规则

1. **等价类划分**：每个可空或可枚举字段至少覆盖「合法值 / 非法值 / `null` / 空串或空白」；枚举字段覆盖全部合法取值与 1 个非法取值。
2. **边界值**：数量、金额、时间、区间一律覆盖「下限 / 下限 − 1 / 上限 / 上限 + 1」；时间边界使用注入 `Clock`，禁止在断言中调用 `LocalDateTime.now()`。
3. **状态矩阵**：状态机逐格覆盖合法迁移、非法跳转、终态重入与终态写操作（UT-018、UT-022、UT-078）。
4. **重复与幂等**：重复提交、重复批次号、5s 窗口重复上报、重复生成检验单、重复发起处置单均有用例。
5. **并发语义**：单元层只验证乐观锁失败分支与幂等窗口的判定逻辑，真实并发竞态由集成测试覆盖（IT-007、IT-016、IT-025、IT-037）。
6. **可测性约束**：时钟、ID 生成器、网关客户端、审计写入器均以接口注入，测试不依赖系统时间与静态单例。

本文件在模板列（用例编号 / 模块 / 优先级 / 前置条件 / 输入 / 预期结果 / Mock 依赖）基础上增加「覆盖需求」列用于机械校验 AC 覆盖，「输入与步骤」列合并模板的「输入」，以 `① ② ③` 标注可独立复现的步骤。

### 执行方式

```text
mvn -B -f backend/pom.xml test                                  # 全量单元测试
mvn -B -f backend/pom.xml test jacoco:report                    # 含 JaCoCo 覆盖率报告
mvn -B -f backend/pom.xml test -Dtest=ConflictDetectorTest      # 单类执行
```

单元测试不启动 Spring 容器、不连接数据库；需要真实数据库的断言一律下沉到集成测试。

追踪标记：每个测试方法在方法注释中声明 `@trace CAP-001 FR-001 AC-001 T-018` 与 `@test-id TEST-MES-018`，`@test-id` 在全仓唯一，供需求—符号—测试追踪桥机械解析；`@trace` 中的任务编号与 `docs/03-任务清单.md` 对齐。

### 关键用例展开（Given / When / Then）

以下 6 条用例承载 P0 规则与已知易错边界，展开为可独立复现的步骤，执行时逐条核对断言要点。

**UT-033 排程区间左闭右开边界（BR-004）**

- Given：设备 `EQ-07` 已有任务 `[09:00, 11:00)`；候选任务 `[11:00, 13:00)`
- When：调用 `ConflictDetector.detect(existing, candidate)`
- Then：冲突集为空；`ScheduleTaskMapper.insert` 执行 1 次
- 断言要点：区间相交判定使用 `candidate.start < existing.end && existing.start < candidate.end`，不得退化为 `<=`，否则首尾相接会被误判为冲突

**UT-053 设备上报 5s 幂等窗口（FR-007 E2）**

- Given：设备 `EQ-07` 于 `10:00:00` 上报 `RUNNING` 并已入库；注入时钟可变
- When：① 时钟推进至 `10:00:04` 再次上报 `RUNNING`；② 推进至 `10:00:06` 上报 `IDLE`
- Then：① 幂等忽略，状态变更记录仍为 1 条，接口返回首次处理结果；② 正常写入第 2 条记录并更新当前状态
- 断言要点：窗口比较使用数据库时间戳与注入时钟的差值，禁止使用 `System.currentTimeMillis()`；比较运算符为 `< 5s` 与 `>= 5s`

**UT-080 超领拦截 105% 边界（FR-010 E3）**

- Given：工单需求量 1000，批次 `LOT-20260401-001` 剩余 2000
- When：① 投料 `1050`；② 投料 `1050.01`
- Then：① 允许，剩余 950；② 抛 `OVER_ISSUE_REQUIRES_APPROVAL`，剩余保持 2000
- 断言要点：阈值计算使用 `BigDecimal` 且 `scale=3`、`RoundingMode.HALF_UP`，不得使用 `double` 相乘

**UT-096 检验容差 ±0.01%（BR-010 例外）**

- Given：数值型检验项 `upperLimit=20.00`、`lowerLimit=10.00`，容差 ±0.01%
- When：① `measuredValue=20.002`；② `measuredValue=20.010`
- Then：① 判定合格（容差内）；② 判定不合格
- 断言要点：容差基准取限值本身（`20.00 × 0.01% = 0.002`），判定顺序为「先比限值，再套容差」，避免容差把超限值拉回合格区

**UT-026 报工乐观锁冲突（AC-006）**

- Given：工单 `WO20260401-0007`，`version=2`，已报 400
- When：① 以 `version=2` 提交 `goodQty=60` 并成功（`version` 变为 3）；② 另一请求以 `version=2` 提交 `goodQty=60`
- Then：① 累计 460；② 抛 `VERSION_CONFLICT`，累计仍为 460，报工记录不新增
- 断言要点：乐观锁以 `updateById` 影响行数为唯一判据（`0` 行即失败），不得在 Service 层做「读后比对」式的伪乐观锁

**UT-044 班次日历配置缺失回退（BR-013 未覆盖分支对应片段）**

- Given：`HolidayConfigMapper.selectByDate("2026-04-05")` 返回 `null`
- When：查询该日期的有效时段
- Then：回退为非工作日判定并输出 `warn` 日志（含日期与配置缺失标记），不抛未捕获异常
- 断言要点：本用例显式覆盖该回退分支，用于降低 `ShiftCalendar` 未覆盖分支占比；配置缺失不得被静默当作工作日
