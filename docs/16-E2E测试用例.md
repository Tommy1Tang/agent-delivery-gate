# E2E 测试用例

> **所属项目**：MES Lite — 轻量级离散制造执行系统
> **测试范围**：主旅程「工单创建下达 → 排程 → 投料开工 → 报工报满 → 检验判定 → 完工关闭」全链路浏览器级 E2E，以及 3 条关键异常拦截路径
> **创建时间**：2026-04-01
> **测试角色**：Browser E2E Engineer
> **执行记录**：`docs/17-E2E测试报告.md`（run #2，2026-04-02，10/10 通过）
> **演示说明**：本文档是 MES Lite 通用离散制造演示交付的一部分；环境、账号、编码、数据与地址均为虚构示例，不对应任何真实企业或生产环境。

## 1. 测试范围

### 1.1 覆盖的用户旅程

| 旅程 | 说明 | 用例 | 用例数 |
| --- | --- | --- | --- |
| J-01 主旅程 | 工单创建与下达 → 批次收货与来料判定 → 自动排程 → 投料绑定与库存扣减 → 开工与报工报满 → 检验判定与工单关闭 → 正反向追溯 | E2E-001 ~ E2E-007 | 7 |
| J-02 异常拦截 | 报工超量拦截、检验未判定时关闭拦截、冻结批次投料拦截 | E2E-008 ~ E2E-010 | 3 |
| **合计** | | | **10** |

主旅程首尾数据一致性要求：J-01 执行完毕后，工单状态为 `CLOSED`、批次 `LOT-20260401-001` 余量为 `800.000`、追溯链路存在 2 条投料边。该一致性由 E2E-006 与 E2E-007 共同断言。

J-02 三条负向用例的 PASS 语义为「系统按契约拒绝且未产生副作用」：同时断言 HTTP 状态码、业务错误码与后置状态三者一致，断言通过即判定 PASS。

### 1.2 不覆盖的范围

| 不覆盖项 | 原因 | 验证归属 |
| --- | --- | --- |
| AC-006 并发报工乐观锁冲突 | 双会话并发在浏览器级 E2E 中时序不可稳定复现 | API 级集成测试（双请求并发提交，断言 409 与数量不重复累加） |
| AC-010 排程无可用设备 | 需要构造工艺路线无匹配设备的种子数据，与主旅程种子冲突 | API 级集成测试 |
| AC-011 同设备排程冲突 | 甘特拖拽的冲突提示需人工观察时间轴，自动化断言成本高 | API 级集成测试 + 人工探索测试 1 轮 |
| AC-013 / AC-015 设备上报、看板刷新与告警升级关闭 | 需要模拟网关持续上报与 10 分钟告警升级窗口，超出本次执行时长预算 | API 级集成测试 + 设备网关模拟器脚本 |
| AC-023 / AC-025 检验项完整性与不合格拦截下游 | 需要构造含超限项的检验单与不合格处置数据 | API 级集成测试（含上下限边界值与容差） |
| AC-026 不合格品处置闭环（含 SCRAP 双人审批） | 涉及 ROLE-01 与 ROLE-05 双角色切换与审批时序 | API 级集成测试 + 手工验收 1 轮 |
| AC-028 数据范围隔离、AC-029 审计不可改删 | 越权与篡改场景属安全评审范围 | 安全评审自动化越权用例（`docs/15-安全评审.md`） |
| Excel 导入与追溯报告导出 | 下载文件校验需独立测试夹具 | 集成测试（文件内容断言） |
| 移动端与低分辨率适配 | 需求范围外（仅桌面浏览器，1920×1080 起） | 不在验证范围 |
| 压测与性能指标（NFR-001 ~ NFR-003、AC-030） | 属性能测试范围，非浏览器 E2E | `docs/06-性能优化说明.md` PERF-001 ~ PERF-007 |

### 2.2 执行命令

```bash
# 启动依赖与种子数据
npm run e2e:seed

# 后端与前端
java -jar target/meslite-app.jar --spring.profiles.active=e2e
npm run dev

# 执行全部用例
npx playwright test --config=e2e/playwright.config.ts --project=chromium --reporter=line,json
```

选择器约定：断言基于 `data-test` 属性（如 `[data-test="work-order-status"]`），不使用易碎的 CSS 层级；文本断言仅用于错误码与提示语语义校验。产物统一落盘于 `e2e/artifacts/`。
